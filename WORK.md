### Everyday loop

```bash
bun run build:android            # web bundle -> dist/client -> android/app/src/main/assets/public
cd android && ./gradlew assembleDebug   # or open in Android Studio and press Run
```

`android/app/src/main/assets/public/` and `assets/capacitor.config.json` are
regenerated by every `cap sync` and are gitignored — never edit them by hand.

### Toolchain (why the Gradle files differ from the stock Capacitor template)

- No system JDK on this Mac; builds use Android Studio's bundled JDK 25:
  `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.
  Android Studio uses it automatically.
- JDK 25 ⇒ Gradle ≥ 9.1 ⇒ AGP ≥ 9.0. The project is on **Gradle 9.7.1 / AGP 9.2.1**
  (what Android Studio 2026.1 bundles), instead of the template's 8.14 / 8.13.
- `android/gradle.properties` sets `android.newDsl=false`: Capacitor's own Gradle
  modules (`node_modules/@capacitor/android/capacitor`, `capacitor-cordova-android-plugins`)
  still use the legacy `android {}` DSL (`lintOptions`, `minSdkVersion`). Our
  `app/build.gradle` already uses the new DSL. The flag disappears in AGP 10 —
  by then upgrade `@capacitor/android` and drop it.
- `android/build.gradle` pins the sub-modules' `buildscript` AGP to the root
  version so Gradle doesn't download a second AGP.
- `./gradlew --warning-mode all` shows "Implicit lookup of properties in parent
  projects" deprecations: that's Capacitor's `variables.gradle` `ext {}` pattern
  (`$androidxAppCompatVersion` etc.), which Gradle 10 will reject. Upstream
  Capacitor issue; `glanceVersion` follows the same pattern on purpose so it
  gets fixed the same way.
- Kotlin is compiled by AGP's built-in Kotlin (KGP 2.2.10). The Compose compiler
  plugin (`org.jetbrains.kotlin.plugin.compose`, same 2.2.10) is applied on `:app`
  because Glance composables need it.

## Widget (Jetpack Glance, 2×2)

Kotlin lives in `android/app/src/main/java/com/roberrini/okayweather/`:

| File | Role |
| --- | --- |
| `widget/WeatherWidget.kt` | The two looks. **Pill**: a 45° capsule (`res/drawable/widget_pill_45.xml`, tinted `GlanceTheme.colors.surface`) with the condition icon on the bottom-left lobe and the temperature on the top-right one; positions are fractions of the square the pill is fitted into (`TEMP_*` / `ICON_*` constants). **Rain card**: when `upcomingRain().hasRain` — the exact rule of the app's "Upcoming rain" section — a rounded square with icon + temperature, the same summary string as the app, and a bitmap area chart of the next hour. |
| `widget/RainChart.kt` | Canvas renderer for that chart (monotone curve, gradient fill, `now/+15/…/+60` axis), mirrors `UpcomingRainChart` in `src/components/UpcomingRainSection.tsx`. |
| `widget/WeatherIcons.kt` | (pack, OWM icon code) → `res/drawable/wi_<pack>_<code>.xml`. All 54 vectors are **generated** — see below. |
| `widget/WeatherWidgetReceiver.kt` | Starts/stops the refresh schedule with the first/last widget instance. |
| `weather/UpcomingRain.kt` | Port of `src/lib/upcomingRain.ts`. **Keep in sync** with the TS file. |
| `weather/WeatherApi.kt` | OWM One Call 3.0 (`current` + `minutely`, metric), same public key as `src/lib/owm.ts`. |
| `weather/WeatherSnapshot.kt` | The stored data (JSON) + a SharedPreferences cache. |
| `weather/WidgetLocation.kt` | Device last-known location if location permission is granted, else Amsterdam — the same fallback the app uses. |
| `weather/WeatherRefresh.kt` | `WeatherRefreshWorker` (CoroutineWorker) + the WorkManager backstop schedule. |
| `weather/WeatherAlarm.kt` | The heartbeat — see **Keeping the widget fresh** below. |
| `weather/WidgetSettings.kt` | Refresh interval and pinned place, written from Settings via the plugin. |
| `plugin/OkayWeatherPlugin.kt` | Capacitor bridge: Material You palette + widget config. |
| `plugin/MaterialYou.kt` | Reads Android's `system_accent*` / `system_neutral*` ramps. |

Data flow: worker → `WeatherStore` (cache) → `WeatherWidget.publish()` writes the
JSON into each widget's Glance state (DataStore) and calls `updateAll()`. The
composable reads `currentState<Preferences>()`; that's what makes an update
recompose an *open* Glance session — reading in `provideGlance` only runs once
per session and showed stale data.

Theme: `GlanceTheme` with no colors = Material You dynamic palette. Background
is `surface` (near-white / near-black), text `onSurface`, so it follows
day/night; the accent container was tried first but clashed with the icons'
purples. Force pure white/black with a `ColorProvider(day, night)` if wanted.

Verified on the `Pixel_10_Pro` AVD: pill and rain card with live OWM data
(Amsterdam in heavy rain flipped it to the card; a mocked LA/Dubai location
showed the pill), light and dark mode, tap opens the app, picker preview.

### Regenerating the widget's icons

The widget can't load SVGs, so every icon exists as a VectorDrawable. After
changing anything under `src/assets/weather-icons-*`, run:

```bash
python3 tools/svg_to_vector.py
```

It rewrites all 54 drawables and handles what the three packs actually use:
paths, circles, rects, polygons, `<use>`, CSS-class fills from `<style>`,
`<g>` nesting, and gradients that inherit through `xlink:href`.

Two things worth knowing about it:

- **Radial gradients are approximated.** SVG gradients carry a transform and
  can be ellipses; Android's `<gradient>` only has a centre and one radius.
  The radius used is `r * sqrt(|det A|)`, which preserves the gradient's
  area. Invisible at icon size on a two-stop shade.
- **Duplicate stops are dropped.** Figma and Illustrator both emit a trailing
  `<stop offset="1"/>` with no colour. SVG treats that as black at exactly
  the end point, so it never shows on the web — but Android blends into it
  and the ramp ends black.

The widget follows the app's icon pack: the Settings screen pushes it through
the plugin, which stores it and re-renders. The pack has to travel in Glance
*state*, not a value read in `provideGlance` — `updateAll()` recomposes but
does not re-run `provideGlance`, so a captured value never changes until the
session restarts. Same trap as the weather snapshot.

## Keeping the widget fresh

The widget used to go stale until the app was opened. The cause was App
Standby: WorkManager periodic work is bucketed, so on a phone whose owner
hasn't opened the app for a day or two a "30 minute" job slips to hours.
Three layers now, strongest first:

1. **`WeatherAlarm`** — `AlarmManager.setAndAllowWhileIdle`, the one
   primitive that still fires during Doze. Inexact on purpose (the system
   batches it, and it needs no `SCHEDULE_EXACT_ALARM`), re-armed after every
   run, cancelled when no widget is placed. Interval comes from Settings.
2. **`updatePeriodMillis=1800000`** — the OS's own widget update. Costs
   nothing, is re-delivered after a reboot, and is where the alarm gets
   re-armed, so the schedule self-heals without a boot receiver.
3. **WorkManager periodic** — survives if an OEM battery manager drops the
   alarm. Uses `UPDATE` so an interval change takes effect.

Plus a 10-minute follow-up while rain is expected, and an immediate refresh
on app resume. Staleness is also visible rather than silent: past 90 minutes
the pill mutes the temperature and shows the observation time.

Note that **no mechanism can fetch during deep Doze** — the system suspends
network for background apps until a maintenance window. The alarm fires
promptly once the device wakes, which is when anyone is actually looking.

## Settings (`src/routes/_tabs.settings.tsx`)

Stored in one localStorage entry (`lib/settings.ts`, `hooks/use-settings.tsx`).

| Setting | Notes |
| --- | --- |
| Theme | system / light / dark. The dark palette already existed in `styles.css` but nothing applied the class. An inline script in `__root.tsx` applies it before first paint. |
| Style | One axis, three looks, set as `data-style` on `<html>`: **modern** (bordered cards, the stock look), **material** (tonal fills instead of borders — `--border` goes transparent and the palette is written inline), **frosted** (translucent cards over a gradient). |
| Colour | Material only: the wallpaper palette (Android 12+) or one of six seeds. A seed is expanded into Material-style tonal ramps by `lib/palette.ts` in OKLCH, producing the same `accent1_600`-shaped map the native plugin returns — so both sources share one code path. On web, "wallpaper" falls back to the brand colour. |
| Icons | **modern** (default, the rounded gradient set), **candy** (glossier, from OkayWeatherV2 "Weather new") or **classic** (the original 2020 set). The picker shows one sample each so it fits three across on a phone. |
| Units | °C/°F, km/h / m/s / mph, 24h/12h. °C and km/h stay internal; only display converts, so `windTier()` thresholds still work. |
| Widget | Refresh interval and device-location vs pinned city, through the plugin. |

### Two traps in the appearance CSS

- **Never write `-webkit-backdrop-filter` next to `backdrop-filter`.**
  lightningcss drops *both* when it sees the duplicate — it already adds the
  prefix itself from browserslist. This silently left the entire frosted
  style with no blur at all, just translucency, which is easy to miss
  because translucency alone still looks plausible.
- **Full-screen sheets need `.app-sheet`.** Frosted sets `--background` to
  fully transparent, so a `fixed inset-0 bg-background` overlay (the day and
  alert views) let the page behind scroll through it and the two layouts
  read as one jumble. `.app-sheet` gives them the page gradient, opaque;
  their own cards still supply the glass. Pinned *bars* keep the
  translucent treatment — that one is deliberate.

## Weather map

- **CARTO basemaps now need a key** (`?key=` on `basemaps.cartocdn.com`);
  without it every tile reads "API KEY REQUIRED". The key lives in
  `src/components/MapPrecipitation.tsx`. Free for non-commercial use to 5M
  tiles/month; the attribution under the map is part of the terms.
- **RainViewer dropped nowcast** from the free feed on 1 Jan 2026 and caps
  tiles at zoom 7 (above that it serves a black "Zoom Level Not Supported"
  tile — the map's `maxZoom` is now 7 to match). No API key exists for it.
- Rain *prediction* is unaffected elsewhere: the "Upcoming rain" section and
  the widget's rain card both come from OpenWeatherMap's free `minutely`
  block, not from the radar map.
