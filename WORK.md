# Android / Capacitor — working notes

Branch: `android-capacitor`. The web app (`src/`, `vite.config.ts`, the Cloudflare
deploy) is untouched; everything Android-specific is additive.

### Everyday loop

```bash
bun run build:android            # web bundle -> dist/client -> android/app/src/main/assets/public
cd android && ./gradlew assembleDebug   # or open in Android Studio and press Run
```

`android/app/src/main/assets/public/` and `assets/capacitor.config.json` are
regenerated by every `cap sync` and are gitignored — never edit them by hand.

### Toolchain (why the Gradle files differ from the stock Capacitor template)

- No system JDK on this Mac; builds use Android Studio's bundled JDK 25:
  `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.
  Android Studio uses it automatically.
- JDK 25 ⇒ Gradle ≥ 9.1 ⇒ AGP ≥ 9.0. The project is on **Gradle 9.7.1 / AGP 9.2.1**
  (what Android Studio 2026.1 bundles), instead of the template's 8.14 / 8.13.
- `android/gradle.properties` sets `android.newDsl=false`: Capacitor's own Gradle
  modules (`node_modules/@capacitor/android/capacitor`, `capacitor-cordova-android-plugins`)
  still use the legacy `android {}` DSL (`lintOptions`, `minSdkVersion`). Our
  `app/build.gradle` already uses the new DSL. The flag disappears in AGP 10 —
  by then upgrade `@capacitor/android` and drop it.
- `android/build.gradle` pins the sub-modules' `buildscript` AGP to the root
  version so Gradle doesn't download a second AGP.
- `./gradlew --warning-mode all` shows "Implicit lookup of properties in parent
  projects" deprecations: that's Capacitor's `variables.gradle` `ext {}` pattern
  (`$androidxAppCompatVersion` etc.), which Gradle 10 will reject. Upstream
  Capacitor issue; `glanceVersion` follows the same pattern on purpose so it
  gets fixed the same way.
- Kotlin is compiled by AGP's built-in Kotlin (KGP 2.2.10). The Compose compiler
  plugin (`org.jetbrains.kotlin.plugin.compose`, same 2.2.10) is applied on `:app`
  because Glance composables need it.

## Widget (Jetpack Glance, 2×2)

Kotlin lives in `android/app/src/main/java/com/roberrini/okayweather/`:

| File | Role |
| --- | --- |
| `widget/WeatherWidget.kt` | The two looks. **Pill**: a 45° capsule (`res/drawable/widget_pill_45.xml`, tinted `GlanceTheme.colors.surface`) with the condition icon on the bottom-left lobe and the temperature on the top-right one; positions are fractions of the square the pill is fitted into (`TEMP_*` / `ICON_*` constants). **Rain card**: when `upcomingRain().hasRain` — the exact rule of the app's "Upcoming rain" section — a rounded square with icon + temperature, the same summary string as the app, and a bitmap area chart of the next hour. |
| `widget/RainChart.kt` | Canvas renderer for that chart (monotone curve, gradient fill, `now/+15/…/+60` axis), mirrors `UpcomingRainChart` in `src/components/UpcomingRainSection.tsx`. |
| `widget/WeatherIcons.kt` | OWM icon code → `res/drawable/wi_*.xml`. Those 18 vectors are **generated** from `src/assets/weather-icons/*.svg` (paths + linear gradients only). Regenerate them if the SVGs change — the conversion is a ~40-line Python script over ElementTree; keep the same file names. |
| `widget/WeatherWidgetReceiver.kt` | Starts/stops the refresh schedule with the first/last widget instance. |
| `weather/UpcomingRain.kt` | Port of `src/lib/upcomingRain.ts`. **Keep in sync** with the TS file. |
| `weather/WeatherApi.kt` | OWM One Call 3.0 (`current` + `minutely`, metric), same public key as `src/lib/owm.ts`. |
| `weather/WeatherSnapshot.kt` | The stored data (JSON) + a SharedPreferences cache. |
| `weather/WidgetLocation.kt` | Device last-known location if location permission is granted, else Amsterdam — the same fallback the app uses. |
| `weather/WeatherRefresh.kt` | `WeatherRefreshWorker` (CoroutineWorker) + scheduling: every 30 min, an immediate run when a widget is placed / the app is opened (`MainActivity.onResume`), and 10-minute follow-ups while rain is expected. |

Data flow: worker → `WeatherStore` (cache) → `WeatherWidget.publish()` writes the
JSON into each widget's Glance state (DataStore) and calls `updateAll()`. The
composable reads `currentState<Preferences>()`; that's what makes an update
recompose an *open* Glance session — reading in `provideGlance` only runs once
per session and showed stale data.

Theme: `GlanceTheme` with no colors = Material You dynamic palette. Background
is `surface` (near-white / near-black), text `onSurface`, so it follows
day/night; the accent container was tried first but clashed with the icons'
purples. Force pure white/black with a `ColorProvider(day, night)` if wanted.

Verified on the `Pixel_10_Pro` AVD: pill and rain card with live OWM data
(Amsterdam in heavy rain flipped it to the card; a mocked LA/Dubai location
showed the pill), light and dark mode, tap opens the app, picker preview.

### Location on the emulator (for testing)
```bash
adb shell pm grant com.roberrini.okayweather android.permission.ACCESS_FINE_LOCATION
adb shell appops set com.android.shell android:mock_location allow
adb shell cmd location providers add-test-provider gps
adb shell cmd location providers set-test-provider-enabled gps true
adb shell cmd location providers set-test-provider-location gps --location 34.0522,-118.2437
adb shell am start -n com.roberrini.okayweather/.MainActivity   # onResume -> refresh
```
`adb emu geo fix` alone is not enough — nothing holds an active GPS request.

## Next steps

### 1. Location in the real app
The manifest now declares `ACCESS_COARSE/FINE_LOCATION`, so the WebView's
`navigator.geolocation` call actually prompts (Capacitor forwards it). Once
granted, the widget uses the device's last-known fix. Worth checking on a
phone that the prompt appears on first launch and that `okayweather.last` in
the app and the widget agree.

### 2. Nice-to-haves
- Refresh on tap-and-hold, or an `ACTION_REFRESH` action on the card.
- `SizeMode.Responsive` variants if you ever allow other cell sizes.
- Show the app's "feels like" / condition text under the temperature on the
  pill for a 3×2 variant.
- A Capacitor plugin bridge (`@capacitor/preferences`) if you'd rather the
  widget follow the *app's* chosen city instead of device location — needs a
  small `src/` change, see the earlier WORK.md revision in git history.

### 4. Release
- Follow Sundial: `keystore.properties` (gitignored) + `signingConfigs` in
  `app/build.gradle`; `./gradlew assembleRelease`.

## Watch-outs when pulling Lovable's changes from `main`

- **`package.json` / `bun.lock`** — the only shared files this branch touches:
  3 `@capacitor/*` entries and the `build:android` / `android:open` scripts.
  If Lovable also edits deps you'll get a trivial conflict: keep both sides,
  then `bun install` (not `--frozen-lockfile`) to re-resolve the lockfile.
- `vite.capacitor.config.ts` relies on `@lovable.dev/vite-tanstack-config`
  ≥ 2.13 forwarding `nitro: false` and `tanstackStart.spa`. If Lovable bumps that
  package, run `bun run build:android` and make sure `dist/client/index.html`
  still appears.
- `.gitignore` / `.prettierignore` have a small appended Android block; Lovable
  rewrites to these files merge cleanly as long as the block stays at the end.
- Nothing under `src/` was changed. Option B above is the first thing that will
  need a `src/` edit — do it through Lovable (or on `main`) so its sync doesn't
  fight the branch.
