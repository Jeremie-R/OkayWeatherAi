# Android / Capacitor — working notes

Branch: `android-capacitor`. The web app (`src/`, `vite.config.ts`, the Cloudflare
deploy) is untouched; everything Android-specific is additive.

### Everyday loop

```bash
bun run build:android            # web bundle -> dist/client -> android/app/src/main/assets/public
cd android && ./gradlew assembleDebug   # or open in Android Studio and press Run
```

`android/app/src/main/assets/public/` and `assets/capacitor.config.json` are
regenerated by every `cap sync` and are gitignored — never edit them by hand.

### Toolchain (why the Gradle files differ from the stock Capacitor template)

- No system JDK on this Mac; builds use Android Studio's bundled JDK 25:
  `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.
  Android Studio uses it automatically.
- JDK 25 ⇒ Gradle ≥ 9.1 ⇒ AGP ≥ 9.0. The project is on **Gradle 9.7.1 / AGP 9.2.1**
  (what Android Studio 2026.1 bundles), instead of the template's 8.14 / 8.13.
- `android/gradle.properties` sets `android.newDsl=false`: Capacitor's own Gradle
  modules (`node_modules/@capacitor/android/capacitor`, `capacitor-cordova-android-plugins`)
  still use the legacy `android {}` DSL (`lintOptions`, `minSdkVersion`). Our
  `app/build.gradle` already uses the new DSL. The flag disappears in AGP 10 —
  by then upgrade `@capacitor/android` and drop it.
- `android/build.gradle` pins the sub-modules' `buildscript` AGP to the root
  version so Gradle doesn't download a second AGP.
- `./gradlew --warning-mode all` shows "Implicit lookup of properties in parent
  projects" deprecations: that's Capacitor's `variables.gradle` `ext {}` pattern
  (`$androidxAppCompatVersion` etc.), which Gradle 10 will reject. Upstream
  Capacitor issue; `glanceVersion` follows the same pattern on purpose so it
  gets fixed the same way.
- Kotlin is compiled by AGP's built-in Kotlin (KGP 2.2.10). The Compose compiler
  plugin (`org.jetbrains.kotlin.plugin.compose`, same 2.2.10) is applied on `:app`
  because Glance composables need it.

## Widget scaffold (Jetpack Glance)

- `widget/WeatherWidget.kt` — `GlanceAppWidget`; renders a static pill
  ("Weather widget — coming soon") on `GlanceTheme.colors.primaryContainer`
  (Material You dynamic color on Android 12+).
- `widget/WeatherWidgetReceiver.kt` — `GlanceAppWidgetReceiver` registered in
  `AndroidManifest.xml`.
- `res/xml/weather_widget_info.xml` — 3×1 cells, horizontally resizable,
  `updatePeriodMillis=0` (refresh will be WorkManager's job).
- `res/values/strings.xml` — `widget_label`, `widget_description`, `widget_placeholder`.
- `androidx.glance:glance-appwidget:1.2.0` (`glanceVersion` in `android/variables.gradle`).

Target design: a single rounded capsule — temperature + condition (+ location),
tap opens the app.

### 1. Wire the widget to real weather data — pick one

**A. Fetch in Kotlin (no `src/` change, widget fully independent)**
- Endpoint the web app uses (`src/lib/owm.ts`):
  `https://api.openweathermap.org/data/3.0/onecall?lat={lat}&lon={lon}&units=metric&appid={KEY}`
  → `current.temp`, `current.weather[0].main`/`.icon`. Add
  `&exclude=minutely,hourly,daily,alerts` to keep the payload small. The key is
  already public in the web bundle; keep it in `local.properties` →
  `BuildConfig` rather than a string literal.
- Location: start with a hardcoded default (the web app's is Amsterdam
  52.3676, 4.9041), then either (i) a widget configuration Activity
  (`android:configure` in `weather_widget_info.xml`) with a city search
  (`/geo/1.0/direct`), or (ii) device location (`ACCESS_COARSE_LOCATION` +
  `FusedLocationProviderClient`). Reading the WebView's `localStorage`
  (`okayweather.last`) from Kotlin is *not* practical — it's a LevelDB under
  `app_webview/`.
- Parse with `org.json` (already on the classpath), store a small
  `WeatherSnapshot` in `SharedPreferences` or DataStore, then
  `WeatherWidget().updateAll(context)`.

**B. Bridge from the WebView via a Capacitor plugin (shares the app's location)**
- `bun add @capacitor/preferences` + `cap sync`. The plugin stores values in
  `SharedPreferences("CapacitorStorage")`, so Kotlin can read them with
  `context.getSharedPreferences("CapacitorStorage", MODE_PRIVATE)`.
- Needs a small `src/` change (coordinate with Lovable): after each successful
  fetch in `src/routes/_tabs.index.tsx`, write the last location
  (`okayweather.last`) and a compact snapshot (temp, condition, icon, ts) with
  `Preferences.set`, guarded by `Capacitor.isNativePlatform()`.
- Optionally a tiny custom plugin (`@CapacitorPlugin class WidgetPlugin`) whose
  `refresh()` method calls `WeatherWidget().updateAll(context)` so the pill
  updates the moment the app has fresh data.
- The widget still needs its own periodic refresh (below) for when the app
  isn't opened.

### 2. WorkManager periodic refresh
- `glance-appwidget` already pulls in `androidx.work:work-runtime`; add
  `work-runtime-ktx` if you want `CoroutineWorker`.
- `WeatherRefreshWorker : CoroutineWorker` → fetch (A) or re-read prefs (B) →
  persist → `WeatherWidget().updateAll(applicationContext)`.
- Enqueue in `WeatherWidgetReceiver.onEnabled()`:
  `WorkManager.getInstance(ctx).enqueueUniquePeriodicWork("weather-refresh", KEEP, PeriodicWorkRequestBuilder<WeatherRefreshWorker>(30, MINUTES).setConstraints(NetworkType.CONNECTED).build())`
  and cancel it in `onDisabled()`. Minimum period is 15 min; 30 keeps
  OpenWeatherMap's free quota comfortable.
- Add an `ACTION_REFRESH` tap action later if you want pull-to-refresh on the pill.

### 3. Pill design pass
- `SizeMode.Responsive(setOf(DpSize(110.dp, 40.dp), DpSize(180.dp, 40.dp), DpSize(250.dp, 40.dp)))`
  → compact (temp only) / regular (temp + condition) / wide (+ location).
- `cornerRadius(28.dp)` is already a capsule at one cell tall; keep
  `maxResizeHeight=40dp`.
- Tap: `GlanceModifier.clickable(actionStartActivity<MainActivity>())`.
- Add `android:previewLayout` (API 31+) and/or `android:previewImage` so the
  widget picker shows the pill rather than the app icon.
- Icons: reuse `src/assets/weather-icons/*.svg` by converting to vector
  drawables (Android Studio: New → Vector Asset → local SVG).

### 4. Release
- Follow Sundial: `keystore.properties` (gitignored) + `signingConfigs` in
  `app/build.gradle`; `./gradlew assembleRelease`.

## Watch-outs when pulling Lovable's changes from `main`

- **`package.json` / `bun.lock`** — the only shared files this branch touches:
  3 `@capacitor/*` entries and the `build:android` / `android:open` scripts.
  If Lovable also edits deps you'll get a trivial conflict: keep both sides,
  then `bun install` (not `--frozen-lockfile`) to re-resolve the lockfile.
- `vite.capacitor.config.ts` relies on `@lovable.dev/vite-tanstack-config`
  ≥ 2.13 forwarding `nitro: false` and `tanstackStart.spa`. If Lovable bumps that
  package, run `bun run build:android` and make sure `dist/client/index.html`
  still appears.
- `.gitignore` / `.prettierignore` have a small appended Android block; Lovable
  rewrites to these files merge cleanly as long as the block stays at the end.
- Nothing under `src/` was changed. Option B above is the first thing that will
  need a `src/` edit — do it through Lovable (or on `main`) so its sync doesn't
  fight the branch.
